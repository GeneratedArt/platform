15. Scoring System
Every project carries a composite GA Score (0-100) plus five dimension scores, all visible on the project page as a radar chart + breakdown.
15.1 Dimensions
A. Code Quality (0-100) — automated, nightly
Computed by workers/audit-scorer running against the GitHub repo at the release tag:

Determinism (25 pts): validate-bundle passed cleanly, no flaky pixel diffs over 10 runs
Bundle efficiency (15 pts): compressed size ratio (< 500KB: 15, <1MB: 12, <2MB: 8, <3MB: 4, >3MB: 0)
Dep hygiene (15 pts): no unused deps, no pinned-to-latest (*), no deprecated packages, allowlist-only imports
Complexity (10 pts): average cyclomatic complexity ≤ 10 per function (using escomplex). Overly obfuscated or minified source loses points (we want readable art)
Comments & docs (10 pts): code-to-comment ratio, README completeness, features documented
Reproducibility (15 pts): package.json lockfile present, build produces identical bundle on two different machines (CI check)
License clarity (10 pts): LICENSE present, matches declared license field, permissive or well-known copyleft

B. Originality (0-100) — automated copycat detection, nightly
workers/audit-scorer also runs:

Visual similarity scan (40 pts): pHash of 10 random captures compared to (a) the artist's prior work, (b) every other GA project, (c) a hash-indexed corpus of fxhash + Art Blocks headline works. High similarity to prior own work is fine; to others' work is flagged.
Code AST similarity (30 pts): tree-edit distance between this project's JS AST and all prior GA projects. Low distance = flagged for curator review.
Feature novelty (20 pts): how many of the project's features (palette algorithms, noise types, shader constructs) are found in prior works of other artists.
Declared inspiration credits (10 pts): if the artist declares inspiration in README and tags the inspirator's wallet, they get full credit here (honesty rewarded).

Flags with similarity > 0.85 go into similarity_flags and require curator adjudication before release. Score < 60 blocks release; curator can override with attestation.
C. Rarity (per edition) — deterministic
Not a project-level score but a per-edition score. Each edition's features (extracted via $ga.features) are hashed; rarity = frequency of that feature combination across the edition set. Standard fxhash-style rarity ranking on the project page.
D. Community Score (0-100) — ratings-driven
Weighted average of ratings from different roles:

Curators × 5
Verified artists × 3
Galleries × 2
Collectors who own an edition × 2
Other collectors × 1

Minimum 10 ratings before the score displays publicly. Each rating is EIP-712 signed; spam / brigade detection by clustering analysis (too many ratings from wallets with no prior activity → weight 0).
E. Market Score (0-100) — on-chain, indexer-computed

Sell-through rate (30 pts): % of edition sold / time since launch
Holder diversity (25 pts): Gini coefficient of holders (lower = better)
Secondary volume (20 pts): Σ(secondary sales) / primary volume, capped at 1.0
Floor stability (15 pts): low volatility of floor over trailing 30 days
Time-weighted trading interest (10 pts): number of distinct secondary buyers

F. Composite GA Score
0.25 × CodeQuality + 0.25 × Originality + 0.20 × Community + 0.20 × Market + 0.10 × normalized-Rarity-distribution-entropy
15.2 On-chain attestations
Every score computation writes an Attestation to ScoreAttestation.sol with:

attester (the Worker's Steward-signed key OR an individual rater's wallet)
projectId (keccak256 of contract address)
dimension (bytes32)
score (uint8)
evidence (IPFS CID of the full audit report JSON — stored in R2 mirrored to IPFS)

This makes scores auditable and historicized. Anyone can verify a score by re-running the evidence against the source.
15.3 Manual overrides
Curators can issue correction attestations if an automated score is clearly wrong (e.g., originality flag was a false positive). These are also on-chain. A display-layer formula prefers the latest Curator attestation if one exists within the last 30 days.
15.4 Display
Every project page and every dashboard card shows:

GA Score as a large pill (color-graded green/amber/red)
Five-axis radar chart (Code, Originality, Community, Market, Rarity-entropy)
Audit trail link → /projects/:slug/audit shows full history of attestations with evidence links
