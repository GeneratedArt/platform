0. Paste-this-to-Replit — Master Prompt
You are building GeneratedArt, a global, decentralized NFT platform and artist collective for code-based generative art (hand-written p5.js / three.js / WebGL / GLSL / Processing / creative-coding in any language — not AI/prompt-generated imagery). Think of it as neutral infrastructure: like OpenSea (agnostic, global, anyone can mint) merged with fxhash (artist-first, deterministic, code-verified). No editorial gatekeeping. No single curatorial direction. All decisions are visible on GitHub and made by elected community curators.
The platform must be operable end-to-end by a decentralized, forked community using only GitHub + Jekyll + Cloudflare + Ethereum/Base. No traditional servers, no AWS, no databases-as-a-service outside Cloudflare's free tier. The source code is the spec. Anyone can audit it, fork the entire org, run a mirror, or propose changes via PR.
Think mirror-able, community-governable infrastructure. Not a company. Not a gated gallery. A public good.
Treat this document as the spec. Work iteratively: scaffold the monorepo first, get the Jekyll public site + one Worker + one smart-contract stub talking to each other, then layer features. Do not try to build everything before the first deploy.

2. Reality-Check Caveats (build these in, don't paper over them)

Jekyll is static. It renders the catalog, artist profiles, and gallery pages from D1 exports committed to the repo during a nightly or post-mint GitHub Actions job. Dynamic views (mint page, wallet-gated pages, dashboards) are Astro/Preact served by Pages and hydrated with Worker APIs.
Cloudflare IPFS gateway is read-only. Pinning happens via Pinata/web3.storage. Wire both as failover. Never rely on the gateway to keep content alive.
Cloudflare Ethereum gateway is RPC. Minting requires the collector's wallet to sign the tx — the platform never holds funds. The Worker only reads chain state and indexes events.
GitHub is the code registry. Each approved generative project lives in its own repo. A Worker uses a GitHub App (not a PAT) to create repos, open PRs, merge, tag, and trigger release workflows. The GitHub App's private key lives in a Worker Secret.
Smart contracts are the ledger. D1 is a cache/index of on-chain state, never the source of truth. Indexer must be re-runnable from genesis.
Community-runnable means: one make bootstrap command, a documented wrangler.toml.example, no proprietary secrets hardcoded, and a CONTRIBUTING.md that explains how to fork the whole org.


3. Personas & Roles

Visitor — browses the catalog, reads about artists, no account needed. Anyone in the world.
Collector — connects a wallet to mint an iteration, view their holdings, resell on secondary. Anyone with ETH/Base.
Artist — signs in with GitHub OAuth + wallet, applies to publish, owns project repos, receives royalties. Anyone (geographically agnostic).
Curator — a community-elected reviewer who approves artist applications and project bundles via GitHub PR reviews. Role is community-voted, not appointed.
Gallery Partner (optional) — a physical or virtual gallery anywhere that curates an exhibition page on the platform, features artists' work, possibly co-creates physical editions (prints, merchandise, plotted output). Completely optional; the platform works without them.
Steward (DAO council) — 5–7 community-elected members who hold the org-level GitHub admin key and a multisig that controls contract upgrades. Quarterly elections, transparent voting on governance proposals.

Role is stored per-user in D1, versioned in a roles.yml commit-history in the org repo for full transparency and auditability.

6. Worker API Contract (Hono on Workers)

Auth: Bearer session token (from GitHub OAuth callback) OR a SIWE (Sign-In With Ethereum, ERC-4361) signature. Both produce a session row.
POST   /auth/github/callback          → session token
POST   /auth/siwe/verify              → session token
GET    /me                            → current user + roles

# Artists

GET    /artists/:slug
PATCH  /artists/:slug                 (self or curator)
POST   /artists/:slug/approve         (curator+)

# Projects

                                      → creates GeneratedArt/art-<slug> repo, returns clone URL
GET    /projects
GET    /projects/:slug
POST   /projects/:slug/submit         → moves status to 'review', opens release PR
POST   /projects/:slug/approve        (curator+) → merges PR, tags release, pins to IPFS,
                                                   calls factory.createProject() via a
                                                   relayer tx signed by the steward multisig

# Mint (frontend talks to chain directly; these are helpers)
GET    /projects/:slug/mint-params    → {contract, price_wei, merkle_proof?}
POST   /projects/:slug/preview        body: {token_hash}  → renders and returns R2 URL of capture

# Editions
GET    /editions/:contract/:token_id

# Galleries

POST   /galleries/:slug/exhibitions   (gallery steward)

# Physical bridge
POST   /editions/:id/request-physical body: {print_spec, dongle}
Every mutating endpoint writes to audit_log before responding.
Rate limiting: 60 req/min per session, 10 req/min unauthenticated, enforced via Cloudflare's KV+Durable-Object token bucket.

7. Smart Contracts
Chain: Base (L2). Rationale: sub-cent mints, EVM compatibility, Coinbase distribution. Testnet: Base Sepolia. All addresses committed to contracts/deployments/<chain>.json.
Contracts:

GenArtFactory.sol — deploys one GenArtProject per approved project. Emits ProjectCreated(address project, string slug, address artist). Only callable by the steward multisig.
GenArtProject.sol — ERC721A with:

uint256 public immutable editionSize;
uint256 public immutable pricePerMint;
string public bundleCID; (IPFS CID of the HTML bundle)
bytes32 public immutable projectSeed; (set at deploy from keccak256(bundleCID, artist, block.number))
mapping(uint256 => bytes32) public tokenHashes; set in _mint via keccak256(abi.encode(projectSeed, tokenId, minter, block.prevrandao))
tokenURI(id) returns ipfs://<metadataCID>/<id>.json; metadata's animation_url is https://renderer.generatedart.com/render?cid=<bundleCID>&hash=<tokenHashes[id]>
EIP-2981 royalties pointing to a RoyaltySplitter


RoyaltySplitter.sol — splits primary + secondary: 85% artist, 10% platform (multisig), 5% gallery (if exhibitedAt != address(0)).

Write Foundry tests covering: determinism of tokenHash, supply cap, royalty math, access control, re-entrancy on mint.
Indexer: A scheduled Worker (workers/indexer) runs every minute. It reads the latest block from Cloudflare Ethereum Gateway, fetches Transfer + ProjectCreated logs, upserts into editions + projects. Re-runnable from block 0 via a ?from= query param.

8. Artist Onboarding & Project Lifecycle
This is the heart of the platform — spend the most design effort here.
8.1 Onboarding

Artist visits /apply, signs in with GitHub.
They complete a profile (bio, portfolio links, wallet address).
Application posts as a GitHub Issue in GeneratedArt/applications via the GitHub App.
Curators review and label approved → a Worker webhook flips the DB row and upgrades the user's role.

8.2 Creating a Project

Approved artist clicks New Project in the Studio dashboard.
Frontend calls POST /projects. The Worker:

Creates repo GeneratedArt/art-<slug> via GitHub App, seeded from templates/fxhash-compatible (an HTML + <script> template with a $ga SDK exposing $ga.hash, $ga.rand(), $ga.features, $ga.preview()).
Adds CODEOWNERS (artist + curators), branch protection on main, PR-required workflow.
Returns clone URL + instructions.


Artist develops locally using a dev container (provided in the template repo) or directly in Replit.
When ready, they open a PR to main with label ready-for-review.
A GitHub Actions workflow (validate-bundle.yml) checks:

Total zipped size ≤ 3 MB
index.html at root
No external network calls (grep fetch(, XMLHttpRequest, import()
Deterministic render: runs the bundle twice with the same hash, diffs pixel output via headless Chromium
Dependency list against an allowlist (p5, three, regl, tone, d3 — no eval, no remote imports)


Curators review; on approval the GitHub App merges, creates tag v1.0.0, triggers release.yml:

Zips main at the tag
Pushes to Pinata + web3.storage, gets CID
Calls POST /projects/:slug/publish with the CID
The Steward signs a factory tx on Base, deploying the project contract
D1 projects.status → live, contract address stored



8.3 Immutability
Once live, the release tag is protected and the IPFS bundle is pinned redundantly. Code is frozen. Artist can propose a v1.0.1 fix that becomes a new project (new contract) if the fix is material.

9. Rendering & Capture Pipeline
Render URL format:
https://renderer.generatedart.com/render?cid=<bundleCID>&hash=<tokenHash>&res=<w>x<h>
Renderer Worker:

Fetches ipfs://<cid>/index.html through the Cloudflare IPFS gateway.
Rewrites a single <script> inject at the top that sets window.$ga = { hash: '<tokenHash>', rand: seeded PRNG from hash, features: {}, preview: () => postMessage('ga:preview') }.
Returns HTML served with a strict CSP: default-src 'self' https://ipfs.generatedart.com; script-src 'unsafe-inline' https://ipfs.generatedart.com; (inline OK inside the sandboxed iframe).
Sets X-Frame-Options: SAMEORIGIN for renderer.generatedart.com only — all embedding pages load it in <iframe sandbox="allow-scripts allow-pointer-lock">.

Capture service: Browser Rendering API (Cloudflare) or a Puppeteer Worker. Triggered per edition at mint time via the Queue. Stores a 2048×2048 PNG to R2 at captures/<contract>/<tokenId>.png, updates editions.preview_r2_key.

10. Gallery Partners & Physical Editions (Optional, Community-Driven)
The platform is digital-first. But galleries, museums, and print studios anywhere can opt in to create complementary physical editions.

Each GenArtProject contract has an optional physicalEditionSize ≤ editionSize parameter.
A gallery partner creates an exhibition (curates a set of projects), and can mint physical editions: framed prints, plotted output, merchandise, etc.
When a collector mints, they can optionally request a co-printed physical edition from a partner gallery. The gallery handles fulfillment (print, frame, ship). The blockchain records ownership; the gallery handles logistics.
The platform provides a /galleries page where any gallery worldwide can list itself, describe its exhibitions, and link back to projects.
Physical editions split royalties: primary goes to the artist; secondary goes to the artist + gallery. Smart contract handles the split.
No single gallery is privileged. No "official" physical presence. Anyone can set up shop.

Galleries are discovered via the platform directory and word-of-mouth in the community.
For MVP: physical editions are out of scope. They can be a V1.1 add-on once the digital marketplace proves itself. But the contract architecture leaves room for them.

13. Community Governance (lightweight, GitHub-native)

Curator elections happen in GeneratedArt/governance via a GitHub Discussions poll. Elected curators get their role flipped in D1 by a Steward.
Project approval requires N-of-M curator approvals via CODEOWNERS + branch protection. No DAO voting for individual projects (too slow). For the MVP: 2-of-5 curators.
Treasury lives in a Safe multisig on Base. The 10% platform cut flows there. Quarterly distributions proposed as issues in governance and executed by Safe signers.
Charter in governance/CHARTER.md, amendable by PR with 4-of-5 curator approvals.

18. Brand & Voice (Global, Community-First)
GeneratedArt is a global public platform, not a branded experience.

Tone: educational, inviting, anti-gatekeeping. Honor the 60-year history of generative art (Vera Molnár, Georg Nees, Manfred Mohr, Sol LeWitt, Herbert W. Franke) and show how this platform is a continuation of that lineage, now decentralized.

Visual identity: Neutral color palette (black, white, high-contrast accent color — let the art speak). Typeface: Inter + JetBrains Mono (nod to code). No hero video. The generative works are the hero. Reference the aesthetic of the fxhash homepage but stripped of any commercial gloss.
The existing generatedart.com domain redirects to the new platform, or becomes a blog/docs hub. Decision is yours, but the brand is reborn as community infrastructure, not inherited.

20. Out of Scope for V1 (don't get distracted)

Physical editions — galleries + prints are a V1.1 expansion, not MVP. The contract reserves the feature, but fulfillment logistics are complex. Ship digital-only first.
Secondary-market order book — use OpenSea/Blur via EIP-2981 royalties until in-house volume justifies custom order book. Link to secondary, don't build it yet.
Multi-chain minting — Base only at launch. Tezos bridge, Solana support, etc. are V2 conversations.
On-chain storage of the bundle — keep code on IPFS. On-chain storage (Art Blocks style) is a research project, not a launch feature. It's also expensive.
Fiat on-ramp — can add Coinbase Pay or Stripe later. MVP assumes collector has ETH/stablecoin already.
Mobile app — the site is responsive. No native app.
Governance token — no $GENART token, no DAO treasury voting on individual projects. Curator voting on PRs is enough for V1. Token economics is a V2 discussion.
Relayer network for gasless mints — minters pay their own gas; it's transparent and low on Base. Relayers = added complexity.

Build the boring, reliable, auditable version first. The generative art community rewards durability, transparency, and code quality over feature novelty.

21. Closing: Why This Stack, Why This Way
This is not a traditional startup pitch. It's an open-source public good masquerading as a marketplace.
Every line of code is auditable. The database schema is in git. The contract ABI is published. The rendering pipeline has no black box. A college student in São Paulo can fork the entire org, run it on her own Cloudflare account, and create a mirror. An artist can pack up and move to a different host if governance goes sideways. No single point of failure. No API keys held by a company that might fold.
This is intentional. Web3 platforms fail when they centralize (see: most NFT marketplaces post-2023). GeneratedArt succeeds by being forkable, auditable, and governable by the community.
The tech stack reflects this: Cloudflare (read-only IPFS, no vendor lock-in), GitHub (the actual ledger of decision-making), Ethereum Base (open, censorship-resistant), open-source tooling everywhere (Foundry, Drizzle, Astro, Jekyll).
